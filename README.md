# 一起把數學玩懂

從特教教師的備課與課堂需求出發，把國小三年級上學期的數學概念、操作教具、練習、遊戲及學習單整合成一套網頁平台。教師可以先了解學生卡在哪個步驟，再選擇圖像、語音、具體操作與提示，協助學生把操作經驗連回數學符號。

線上展示：[開啟一起把數學玩懂](https://jerryyang2.github.io/grade3-math-toolkit/)

本專題採 **AI 協作開發**。我希望呈現的不只是功能數量，也包括如何理解使用者需求、處理狀態與資料語意，以及驗證題目、圖像和紙本輸出是否一致。現有功能與測試不能直接證明學生的學習成效。

## 為什麼做這個專題

對需要學習支持的學生而言，同樣是算錯，背後可能是讀題困難、位值混淆、忘記進退位，或尚未理解平分的意義。如果只增加題量，教師不一定能看出原因。另一方面，備課素材、教具、題庫與觀察紀錄分散在不同地方，也會打斷課堂流程。

本專題嘗試把「教概念、動手做、做練習、觀察需要的支持」接在一起。主要使用者是國小特教與需要調整教材的教師；學生在教師引導下操作。活動是否合適、提示如何減少，以及能否轉移到生活情境，仍需由教師依個別需要判斷。

教材目前有 **9 個單元、27 個小節與 270 題固定練習**，涵蓋數到一萬、四位數加減、乘法、毫米、角與四邊形、除法、公升與毫升、分數及圓。

「森林拔河運動會」共用這份正式題庫，可篩單元、小節與難度，提供雙隊同機與電腦陪練；預設不限時，答錯不倒退。結果分開記錄首次獨立答對與提示／重試後完成，僅供當回合回顧。六款遊戲皆可從卡片直接進入全螢幕，切換顯示時保留同一個遊戲頁面。

列印功能提供 27 份小節學習單與 9 份單元複習，共 36 份，每份十題，合計 360 個題目位置。複習單使用既有題庫，因此不能說成 360 道不同的新題目。操作教具另有程式產生的練習，也不與固定題庫數量混算。

「教學輔助功能」中的課堂計時器可用於練習、考試或分組活動。由教師決定是否開始、暫停、加時或顯示秒數；縮成小卡仍繼續倒數，關閉面板則暫停。可拖曳標題移動、拖曳四角或邊框調整大小，數字隨視窗放大。右上角提供獨立全螢幕倒數與還原大小；全螢幕的齒輪按鈕可展開計時設定。提示音預設關閉，全螢幕上課也可開啟；重新載入網頁後不保留計時狀態。

## 三個可以閱讀原始碼的設計案例

### 保留首次作答，避免把提示後完成當成獨立完成

學生第一次答錯、看過提示後再答對，紀錄應保留首次結果。`recordAttempt()` 以回合、學生與題目識別同一筆觀察，分開保存 `firstCorrect`、`firstSupport`、`finalCorrect` 與 `attempts`；同題重做不會重複增加觀察筆數，也不反覆領取獎勵。

`summarize()` 另外計算首次答對與獨立首次答對。這些欄位表達的是作答過程，不能只因最後完成就推論已精熟。相關程式與案例在 [learning-records.js](js/learning-records.js) 及 [learning-records.test.cjs](tests/learning-records.test.cjs)。

### 把「工具列擋住畫面」拆成操作條件

工具列能拖動只是起點，還要處理輕微晃動、拖到邊緣、切換方向與視窗改變。浮動工具以 Pointer Events 管理操作，計算移動距離，再依可視範圍限制位置；排列方向以 localStorage 記住。

畫記則以目前狀態、過去與未來的堆疊支援復原與重做，並限制歷史與圖形數量。這個案例讓我接觸事件生命週期、座標邊界及記憶體使用，而不只是調整按鈕樣式。對應 [floating-tools.js](js/floating-tools.js) 與 [floating-tools.test.cjs](tests/floating-tools.test.cjs)。

### 題目正確之外，圖像與列印也要一致

量尺刻度、量杯水位、分數等分與除法直式，都必須對應題目的數值與條件。圖像檢核保留題目特徵，修改內容後不能直接沿用過期的審查結果。學習單排版也核對每份題目數、範圍、圖像與計算格。

本機 PDF 同步流程以 SHA-256 核對來源與產物，並驗證 36 份學習單的 360 個題目位置。雜湊只能偵測變動，不能自動證明數學概念與排版正確，因此仍需要人工看題意與列印結果。相關檔案是 [worksheet-visual-data.js](js/worksheet-visual-data.js)、[worksheet-layout.js](js/worksheet-layout.js) 與 [sync-worksheet-pdf.cjs](scripts/sync-worksheet-pdf.cjs)。

## 技術架構

網站使用 HTML、CSS 與原生 JavaScript，日常瀏覽不需打包。課程、題目與單元 ID 由資料模組提供，介面、練習與學習單共同使用。部分模組可同時在瀏覽器與 Node.js 執行，讓資料與規則能接受自動測試。

```text
課程與題庫 data.js
       ├── 備課、課堂教學與操作教具
       ├── 隨堂練習 ── 作答紀錄 ── 瀏覽器 localStorage
       └── 學習單資料 ── 共用排版 ── 列印視窗／本機 PDF

單元任務 curriculum.js ── Three.js 群島與互動任務
中文顯示文字 ── 本地英文對照 ── 中英介面與朗讀選擇
```

| 技術 | 用途與界線 |
| --- | --- |
| JavaScript 與 DOM | 教材呈現、操作教具、練習及事件處理 |
| SVG、CSS 與 Three.js | 教學圖像、角色、工具與群島場景；3D 引擎使用既有套件 |
| Pointer Events | 拖曳與畫記操作，搭配座標邊界與中斷處理 |
| localStorage | 裝置上的學生代號、設定、進度與作答紀錄；不是跨裝置資料庫 |
| 中文音檔與 Web Speech API | 朗讀支持；裝置、語音清單及播放限制仍需實測 |
| Node.js test runner、Acorn、LinkeDOM | 規則、語法、資料與部分介面流程測試 |
| Python、ReportLab、pypdf | 本機學習單 PDF 的產製、頁面與題目驗證 |
| GitHub Actions 與 Pages | 通過檢查後部署靜態網站，不執行學生端生成式 AI |

## 本機啟動與驗證

於專案根目錄執行以下指令，需要 Python 3：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

瀏覽器開啟 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)，停止時在終端機按 `Ctrl+C`。瀏覽網站不需要安裝 npm 套件。

執行開發檢查則需 Node.js 與 npm：

```bash
npm ci --ignore-scripts
npm test
npm run i18n:check
npm run audio:check
npm run islands:audio:check
```

本版整理時，既有 **186 項自動測試**通過；雙語檢查涵蓋 270 題及 7 個頁面，另核對中文朗讀與群島語音清單。計時器測試包含背景分頁恢復、暫停、加時上限及小卡操作。這些數字說明檢查範圍，不代表所有裝置、所有操作或教學成效都已驗證。

維護端另執行 `npm run worksheets:pdf:check` 與 `npm run manual:check`。這兩項需要本機教材、私有手冊與覆核資料；公開儲存庫不包含這些產物，因此僅下載原始碼不能直接重現完整的出版品驗收。

## 建議的專題展示流程

1. 選擇位值單元，從常見迷思進入教具，示範百位為零與滿十進一。
2. 用虛構學生代號做一題練習，先答錯、看提示再答對，說明首次結果與最後完成的差別。
3. 拖曳與切換浮動工具方向，展示畫記、復原及邊界處理。
4. 開啟同一小節的學習單預覽，對照題意、圖像與計算空間，再展示群島中的單元任務。

展示時使用虛構資料，並選擇自己能解釋的程式案例。若用截圖備援，應清楚標示為截圖，不冒充現場操作或學生實測結果。

## AI 協作與我的分工

本專題的大量程式由 Antigravity、Codex 等 AI 工具協助草擬、修改與除錯。我主要負責理解教學使用者的情境、整理需求、提出驗收條件、操作與回報問題，再逐步閱讀程式；教材適切性與課堂取捨需要教師參與判斷。

AI 也協助翻譯、測試與文件整理。我不把所有程式都稱為獨立手寫，也不把能描述需求等同於已能獨立設計整個系統。接下來的學習重點，是選取數線、首次作答紀錄與拖曳等小範圍功能，先畫出流程與測試案例，再練習離開既有答案自行實作。

這次實作讓我對資訊工程的問題更具體：資料欄位如何影響使用者判斷、事件與狀態如何保持一致，以及怎樣把重複檢查變成可維護的流程。我希望持續補強程式設計、資料結構、軟體工程與人機互動的基礎。

## 目前限制與後續方向

- 網站以本機瀏覽器保存紀錄，沒有帳號隔離、自動跨裝置同步或可靠的雲端備份。實際學生資料不應放入公開原始碼，示範資料與真實觀察須分開解讀。
- 現有觀察與功能展示不能作為學習成效研究。後續應先定義任務、提示條件與觀察方式，再評估操作是否改善，以及學生能否把概念帶到不同材料或情境。
- 語音、畫記、較大字級與其他支持工具不代表已符合所有無障礙需求。瀏覽器、觸控、投影與列印仍需要實際測試；螢幕量尺也不能當作測量實物的標準尺。
- 部分模組仍依賴全域狀態與載入順序，教材與顯示邏輯尚可進一步拆分；未來優先改善資料介面與常出錯流程的回歸測試。
